# 05. 프론트엔드 노선도 시각화 설계

전제: `04-api-design.md`의 API(특히 `/api/diagram`, `/api/stations/search`, `/api/stations/{id}`)를 소비하는 클라이언트를 설계한다. F1(노선도 시각화), F2(검색), F5(인터랙션), F6(범례)를 다룬다.

## 1. 기술 스택 (확정)

빌드 툴체인 없이 **순수 HTML/CSS/바닐라 JavaScript**로 진행한다. 내부 도구 규모에서 검색 자동완성, SVG 노선도, 상세 패널 정도의 상호작용은 프레임워크 없이도 충분히 구현 가능하고, 다음 이점이 크다.

- npm/Vite/React 등 빌드 파이프라인이 없어 **배포가 단순**함 — 정적 파일을 `src/main/resources/static`에 두기만 하면 Spring Boot가 그대로 서빙.
- 의존성이 거의 없어 유지보수 부담이 적고, 내부 도구 특성상 화면 복잡도가 과도하게 커질 가능성이 낮음.
- 브라우저 네이티브 ES 모듈(`<script type="module">`)로 파일을 기능 단위로 분리해 구조는 유지하면서 빌드 스텝은 생략한다.

- **렌더링 방식**: **SVG**. `document.createElementNS`로 노선/역 요소를 직접 생성. 역 수가 많아도(수천 개 이하 추정) DOM 성능에 큰 문제가 없고, CSS로 스타일링(hover, 하이라이트)이 쉽다.
- **상태 관리**: 별도 라이브러리 없이, 화면 상태(검색어/선택된 역/선택된 노선/하이라이트)를 담는 단순한 JS 객체 하나와, 상태 변경 시 관련 DOM을 다시 그리는 작은 렌더 함수들로 구성(간이 옵저버 패턴 정도로 충분).
- **파일 구조 (제안)**:

```
src/main/resources/static/
 ├─ index.html
 ├─ css/
 │   └─ style.css
 └─ js/
     ├─ api.js          // fetch 래퍼 (검색/역상세/노선/다이어그램 호출)
     ├─ state.js         // 화면 상태 + 구독/발행
     ├─ search.js        // 검색창, 자동완성
     ├─ diagram.js        // SVG 노선도 렌더링, 줌/팬
     ├─ detailPanel.js     // 역 상세 패널
     └─ main.js          // 초기화, 모듈 연결
```

- **배포 방식**: 별도 빌드 스텝 없이 정적 파일을 그대로 Spring Boot 안에 포함해 **애플리케이션 하나로 배포**한다.

## 2. 도식화(스키매틱) 레이아웃 전략

전체 107개 노선을 지하철 노선도 수준으로 한 번에 자동·정교하게 배치하는 것은 상당히 난도가 높은 과제(옥틸리니어 그래프 드로잉 문제)다. 현실적인 완성도를 위해 **3단계로 나눠 접근**할 것을 제안한다.

### 2.1 Stage A — 노선 단일 뷰 (우선 구현)

노선 하나를 선택했을 때, 그 노선에 속한 역들을 **가로 일직선(또는 완만한 꺾임)으로 균등 간격 배치**해서 보여주는 뷰. 좌표 계산이 단순해 알고리즘으로 자동 생성 가능(역 개수만큼 x축을 균등 분할, 환승 여부는 마커로만 표시). `LineStation.sequence_no` 순서만 있으면 백엔드 좌표 없이도 프론트엔드에서 즉시 계산 가능 — **`diagram_x/y`가 비어 있어도 동작하는 fallback 뷰**로 우선 구현한다.

### 2.2 Stage B — 지역(본부) 단위 통합 뷰

한 본부 관할 구역 내 여러 노선이 교차하는 모습을 보여주는 중간 규모 뷰. 노선 수가 상대적으로 적어(대부분 본부는 노선 10~20개 내외) 수작업으로 `diagram_x/y`를 배치할 수 있는 범위. `03-data-source.md`의 본부별 데이터 구축 순서와 맞물려, 데이터가 채워진 본부부터 이 뷰를 완성해간다.

### 2.3 Stage C — 전국 통합 뷰 (장기 목표)

모든 노선을 하나의 화면에 겹쳐 보여주는 최종 형태. 데이터/좌표가 충분히 쌓인 뒤 착수하며, 1차 배포 범위에는 필수로 포함하지 않는다(내부 도구이므로 검색 → 역 상세, 노선 선택 → Stage A/B 뷰만으로도 핵심 요구사항 F1~F4 충족 가능).

### 2.4 공통 레이아웃 규칙

- 노선은 가급적 **수평/수직/45도 대각선**만 사용해 꺾이도록 배치(지하철 노선도 관례).
- 역 간 간격은 실제 거리(km)에 비례시키지 않고 **가독성 우선으로 균등/유사 간격**을 기본으로 하되, 상세 정보(거리 km)는 클릭 시 텍스트로 정확히 제공.
- 환승역은 모든 소속 노선에서 동일한 좌표 한 점을 공유(02-data-model.md 2.5절과 동일 원칙).

## 3. 화면 구성 (DOM/모듈 단위)

컴포넌트 프레임워크가 없으므로 "컴포넌트"는 **HTML 영역 + 이를 담당하는 JS 모듈**로 대응한다.

```
index.html 레이아웃                담당 모듈
 ├─ #search-bar            (F2)  →  search.js
 ├─ #diagram-view           (F1/F5) →  diagram.js
 │   ├─ <svg> 안의 노선(line) 요소
 │   ├─ <svg> 안의 역(station) 요소
 │   └─ #legend             (F6)  →  diagram.js 내 범례 렌더 함수
 ├─ #line-list-sidebar        (F4)  →  main.js (노선 목록 fetch/렌더)
 └─ #station-detail-panel      (F3)  →  detailPanel.js
```

각 모듈은 `state.js`가 관리하는 상태(선택된 역/노선 등)를 구독해 자신이 담당하는 DOM만 다시 그린다.

## 4. 상호작용 흐름

| 동작 | 처리 |
|---|---|
| 검색창에 입력 | `/api/stations/search?q=` 디바운스 호출(예: 200ms) → 드롭다운에 후보 표시 |
| 검색 결과 선택 | `/api/stations/{id}` 호출 → `StationDetailPanel` 표시 + `DiagramView`에서 해당 역으로 팬 이동 및 하이라이트 |
| 노선도에서 역(점) 클릭 | 검색 결과 선택과 동일하게 상세 패널 표시 |
| 노선 목록에서 노선 선택 | 해당 노선 전체를 하이라이트, 나머지 노선은 dim 처리, Stage A(노선 단일 뷰) 또는 해당 노선이 지나는 Stage B 뷰로 전환 |
| 줌/팬 | 마우스 휠/드래그(데스크톱), 핀치/드래그(모바일) — SVG `viewBox` 조작 방식 사용, 별도 무거운 라이브러리 없이 자체 구현 가능한 범위 |

## 5. 반응형/모바일 대응

- 데스크톱: `StationDetailPanel`을 우측 고정 패널로 표시, `DiagramView`와 동시에 보임.
- 모바일(좁은 화면): `StationDetailPanel`을 하단 바텀시트로 전환, 노선도 위에 오버레이. `LineListSidebar`는 햄버거 메뉴/드로어로 축소.
- 브레이크포인트는 구현 시 일반적인 기준(예: 768px) 사용.

## 6. 데이터 없는 상태 처리

- `diagram_x/y`가 없는 역(Phase 2/4 진행 중 아직 좌표 미배치)은 Stage A 뷰(자동 균등 배치)로 항상 폴백 가능하므로, 데이터 구축이 완료되지 않은 노선도 검색·상세 조회 기능은 처음부터 100% 동작한다. 이는 이 프로젝트가 단계적으로 문서/데이터를 채워나가는 방식과 맞물려, **뷰가 데이터 완성도에 따라 점진적으로 고도화**되는 구조를 보장한다.

## 8. 공유 구간 표시 (2026-09-21)

전체 지도에서는 연속한 두 역의 ID 쌍을 방향과 무관하게 묶어 구간을 한 번만 그린다.
여러 노선이 같은 구간을 사용하면 회색, 단독 구간은 해당 노선 색으로 표시한다.
단순 교차나 가까운 좌표만으로는 서로 다른 선로를 합치지 않는다. 정차역 목록이 다른
운행계통의 건너뛰는 구간까지 동일 선로로 추론하지는 않는다.

왼쪽 목록에서 노선을 선택하면 기본 연결망은 흐리게 하고, 원래 역 순서에 따른 전체
경로 하나를 그 위에 해당 노선 색으로 표시한다. 이 경로는 역 마커보다 아래에 놓인다.
다른 노선을 선택하면 같은 강조 요소의 경로를 교체하며, 같은 노선 재선택 또는 전체 보기로
해제한다. 검색으로 선택한 역은 관련 없는 노선이 선택되어도 보이게 유지한다.
공유 구간의 툴팁에는 소속 노선을 모두 표시하고, 노선 선택은 목록에서 한다.
