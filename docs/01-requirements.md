# 01. 요구사항 정의

## 1. 목적 및 배경

KORAIL 전국 철도노선도(2026.01.01 기준)는 지리적 지도 위에 노선·역·역간 거리(km)가 표기된 자료다. 이 자료를 실제 지도가 아니라 **지하철 노선도 스타일의 도식화된 다이어그램**으로 재구성하고, 역 이름을 검색하면 해당 역이 속한 노선과 관련 정보를 확인할 수 있는 웹 서비스를 만든다.

## 2. 범위

### 2.1 노선 범위 — 전체 107개 노선 (확정)

원본 지도에 표기된 KTX/고속철도, 일반철도, 광역전철, 화물전용선을 포함한 **전체 107개 노선(4,475.8km)**을 모두 데이터 구축 대상으로 한다. 여객/화물 여부로 노선을 구분하지 않고 전량 반영한다.

데이터 입력량이 크므로, 구축 순서는 운영본부 단위(서울본부 → 수도권서부본부 → … 등 지도상 구분 단위)로 나누어 단계적으로 진행하는 것을 제안하되, 최종적으로는 전체 노선을 포함한다.

### 2.2 역 종류 범위 — 전체 역/시설 포함 (확정)

원본 지도 범례상 모든 역 종류(관리역, 고속열차 정차역, 직원배치역, 배치역, 위탁역, 화물취급역, 무인역, 신호소, 임시승강장)를 데이터 구축 및 검색·표시 대상에 포함한다. 화물취급역·신호소처럼 여객이 이용하지 않는 시설도 노선도 상에 표시하고 검색 가능하게 하되, UI 상 아이콘/필터로 여객 이용 가능 여부를 구분해서 보여준다(예: 화물취급역은 다른 마커 스타일 사용).

### 2.3 범위 외 (Out of Scope)

- 실시간 열차 운행 정보(시각표, 지연 정보, 실시간 위치) — 본 서비스는 **정적인 노선/역 구조 정보** 제공에 한정
- 운임 계산, 경로 탐색(환승 최단 경로 안내)은 1차 범위에서 제외하고 이후 확장 과제로 남김

## 3. 사용자 시나리오

| # | 시나리오 | 설명 |
|---|---|---|
| 1 | 역 이름 검색 | 사용자가 검색창에 역 이름 일부를 입력 → 자동완성으로 후보 표시 → 선택 시 해당 역이 속한 노선(들), 인접역, 역간 거리, 역 종류 정보 표시 |
| 2 | 노선도에서 역 확인 | 도식화된 전체(또는 노선별) 노선도에서 역을 클릭 → 위 시나리오 1과 동일한 상세 정보 표시 |
| 3 | 노선 단위 탐색 | 노선 이름으로 검색하거나 목록에서 선택 → 해당 노선의 전체 역 목록(순서대로)과 노선도 상 위치 하이라이트 |
| 4 | 환승역 확인 | 두 개 이상의 노선이 만나는 역 클릭 시, 각 노선별 정보가 구분되어 표시 |

## 4. 기능 요구사항

- **F1. 노선도 시각화**: 노선을 실제 지리 좌표가 아닌 정렬된 도식(직선/사선 위주)으로 렌더링. 노선별 색상 구분, 환승역은 별도 마커로 표시.
- **F2. 역 검색**: 한글 역 이름 부분 일치 검색, 자동완성 지원.
- **F3. 역 상세 정보**: 소속 노선명, 인접역, 인접역까지의 거리(km), 역 종류(관리역/무인역 등), 소속 운영본부.
- **F4. 노선 상세 정보**: 노선에 속한 역을 순서대로 나열, 노선 총 거리, 노선 구분(고속철도/일반철도/광역전철 등).
- **F5. 노선도 인터랙션**: 확대/축소, 이동(팬), 역 클릭 시 상세 정보 패널 표시.
- **F6. 범례 표시**: 원본 지도의 역 종류·선로 종류 범례를 웹에서도 확인 가능하도록 제공.

## 5. 화면 요구사항 (초안)

- **메인 화면**: 상단 검색창 + 전체(또는 대상 범위) 노선도. 지하철 노선도 앱과 유사한 레이아웃.
- **검색 결과/상세 패널**: 화면 우측 또는 하단 사이드 패널로 표시하며, 노선도와 함께 볼 수 있어야 함(모바일에서는 바텀시트 등 고려).
- **노선 필터**: 특정 노선만 선택해서 보이거나 흐리게 처리하는 필터 기능(선택 사항, 우선순위는 낮음).

## 6. 비기능 요구사항

- **반응형**: 데스크톱/모바일 브라우저 모두 지원.
- **성능**: 검색 응답은 체감상 즉시(수백 ms 이내), 노선도는 초기 로딩 후 클라이언트 사이드에서 빠르게 인터랙션 가능해야 함.
- **데이터 갱신**: 원본 KORAIL 노선도는 주기적으로 개정되므로(예시 자료 자체가 "2026.01.01 기준" 버전 표기), 노선/역 데이터를 갱신할 수 있는 구조로 설계(수동 갱신도 허용, 실시간 자동 연동은 범위 외).
- **정확성보다 가독성 우선**: 지하철 노선도와 마찬가지로, 실제 거리·각도보다는 노선 간 관계와 역 순서를 명확히 보여주는 것을 우선한다. 단, 역간 거리(km) 데이터 자체는 정확히 보존하여 상세 정보에 표기.

## 7. 서비스 목적/대상 (확정)

- **내부 도구**로 사용할 목적의 서비스다. 불특정 다수를 위한 공개 서비스가 아니므로, 대외 공개 수준의 UI 완성도·SEO·대규모 트래픽 대응보다는 **정확성과 실무 활용성**(빠른 역/노선 조회)을 우선한다.
- 인증/권한 관리는 내부망 접근 또는 간단한 접근 제어 수준으로 충분하며, 별도 회원 시스템은 필요 없다(추후 필요 시 확장).
- 비기능 요구사항 중 "반응형"·"성능" 항목은 내부 사용자(소수) 기준으로 재조정 가능하나, 데스크톱/모바일 겸용은 유지한다.
